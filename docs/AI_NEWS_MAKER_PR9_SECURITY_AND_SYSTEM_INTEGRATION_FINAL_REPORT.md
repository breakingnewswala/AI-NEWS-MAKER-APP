## 3. ELIMINATION OF BROAD 30-DAY HMAC TOKEN GRACE PERIOD (PHASE 2)

### Vulnerability Identified
Previously, `verifyAuthToken(tokenStr, allowGraceSeconds = 86400 * 30)` allowed expired access tokens up to 30 days old to authenticate administrative and user endpoints, bypassing session expiration checks.

### Remediation Applied
1. Removed `allowGraceSeconds` parameter from `verifyAuthToken()`. Any access token where `payload.exp < nowSec` is strictly rejected with HTTP 401 Unauthorized.
2. Refactored `/api/auth/refresh-session`:
   - Requires an active, non-expired session token OR an authoritative identity token from Google OAuth / Firebase Admin SDK.
   - Verifies the user exists in `loadUsersMasterDatabase()`.
   - Rejects blocked users (`u.isBlocked === true`) with HTTP 403 Forbidden.
   - Rejects deleted or disabled users with HTTP 403 Forbidden.
   - Authoritatively applies server-side role changes (upgrades/downgrades) upon session refresh.

## 4. ELIMINATION OF INSTANCE-LOCAL `.session_secret_vault` (PHASE 3)

### Vulnerability Identified
`server.ts` attempted to persist an autogenerated session secret to disk at `data/.session_secret_vault`. On Cloud Run / Firebase App Hosting, container instances are ephemeral and scale across multiple distinct VMs; different container instances would read or generate differing secrets, invalidating user sessions randomly.

### Remediation Applied
1. In production (`NODE_ENV === "production"` or `K_SERVICE` or `FIREBASE_APP_HOSTING`):
   - Server strictly requires `process.env.SESSION_SECRET` (minimum 32 characters).
   - If missing or insecure, the server refuses to start with an explicit, actionable startup error directing configuration via Google Cloud Secret Manager.
2. In local development or isolated automated testing (`IS_TEST_ENV === "true"`):
   - Generates an in-memory ephemeral random secret (`crypto.randomBytes(32).toString('hex')`) with zero persistent disk leakage.

## 5. AUTHORITATIVE FIRESTORE KEY POOL & NON-DESTRUCTIVE RECONCILIATION (PHASE 4)

### Data Risk Identified
`getOrLoadApiKeysVault()` previously fell back to merging local JSON files into the Firestore vault whenever Firestore returned 0 free keys. This caused deleted or rotated API keys to silently resurrect from local files and overwrite administrator changes.

### Remediation Applied
1. **Firestore is Authoritative:** Removed silent local-to-Firestore auto-merging.
2. **Discrepancy Detection (`sourceMismatch`):** When Firestore key counts differ from local disk files, a `lastSourceMismatchInfo` telemetry object is recorded and returned to the Master Admin in `GET /api/admin/api-keys`.
3. **Explicit Reconciliation (`POST /api/admin/api-keys/reconcile`):** Added explicit admin endpoint allowing Master Admin to explicitly push or pull keys between local files and Firestore on demand without silent background overwriting.
4. **Credential Masking:** Raw API keys are never exposed in JSON responses (`maskApiKey` masks all returned keys).

## 9. SECURE PUBLIC UNBLOCK REQUEST OTP FLOW (PHASE 8)

### Security Gaps Remedied
Previously, anyone could submit an unblock request for any email address without verification, and duplicate pending requests were not prevented.

### Implementation
1. **Verification Request (`POST /api/support/unblock-request/send-verification`):**
   - Authoritative verification: Checks if user exists in database (rejects unregistered with 404).
   - Block status check: Verifies user is actually blocked (rejects active users with 400).
   - Duplicate prevention: Verifies no pending unblock request exists for this email/mobile (rejects with 400).
   - Rate limit: 60-second cooldown between OTP requests.
   - Generates cryptographically secure 6-digit OTP stored in `unblockVerificationStore` with 10-minute expiration and max 5 attempts.
2. **Submission (`POST /api/support/unblock-request`):**
   - Requires and validates the 6-digit OTP.
   - Consumes OTP upon successful validation.
   - Saves verified unblock ticket to support database.
3. **Atomic Admin Approval (`POST /api/admin/unblock-requests/action`):**
   - Admin approves ticket -> authoritatively clears `isBlocked = false`, updates database, and updates user profiles in all layers.

## 10. TEST USER SEGREGATION WITHOUT FALSE POSITIVES (PHASE 9)

### Issue
Substring heuristic filtering (`email.includes('test')`) previously caused false positives on legitimate reporter accounts with names or words containing "test".

### Correction
Refactored `isSyntheticTestAccount(u)` in `AdminPlansAndPackagesManager.tsx`:
- Strictly relies on authoritative flags: `u.isTestUser === true || u.isSynthetic === true || u.accountType === 'test' || u.tier === 'test'`.
- Strict test domain matching: `email.endsWith('@synthetic.local') || email.endsWith('@test.local') || email.endsWith('@example.com')`.
- Strict synthetic prefixes: `email.startsWith('synthetic_') || email.startsWith('e2e_test_')`.
- Zero false positives on legitimate accounts.

## 11. CLOUD SCHEDULER DURABLE 15-MINUTE RSS SYNC (PHASE 10)

   - `GET /api/scheduler/rss-sync`: Returns telemetry and lease lock status.

## 12. SINGLE NEWS POST BY ID & READ-ONLY NEWS DETAIL POPUP (PHASE 11)

### UX Defect Remedied
When a user clicked a news notification in the top bar, the app dispatched `handleDeepLinkPost`, which immediately called `handleOpenStudioWithNews()`, consuming daily generation quota and forcing the user into the photo editor without consent.

### Implementation
1. **API Endpoint (`GET /api/news-posts/:id`):**
   - Fetches individual news post by ID.
   - Enforces approval status, rejection filtering, and privacy rules for non-admin callers.
   - Merges editorial overrides (`approvedPhotos`, `categoryName`, etc.).
2. **Read-Only Popup (`NewsDetailModal.tsx`):**
   - Displays clean, responsive popup showing image, category badge, location, dynamic publication time, headline, full description, and news source.
   - Features an explicit, optional button "इस खबर से ग्राफिक बनाएं" if the user voluntarily decides to design a graphic.
3. **Decoupled Notification Handler (`src/App.tsx`):**
   - `handleDeepLinkPost` now fetches missing posts via `/api/news-posts/:id` and sets `activeNewsDetailPost(targetPost)`, opening `<NewsDetailModal>` without launching the studio or auto-generating graphics.
